# Contributing

Thanks for looking. This repository is the open-source, chain-side part of an EURC escrow rail
on Stellar. It is **testnet only** and **unaudited**; keep it that way in every change.

## Ground rules

- **Standalone.** Nothing here may import a marketplace's private system (its backend, database,
  auth, cloud or payment-provider code). Where a marketplace plugs in, add or extend a small typed
  port with an in-memory implementation, and test against that.
- **Testnet only.** Scripts deploy and send to testnet only (`assertTestnet` guards every entry
  point). Mainnet addresses and Wasm hashes may appear as documented references, never as a
  deploy or submit target.
- **No secrets, ever.** No Stellar secret seed (`S...`), seed phrase, API key, `.env` file or JSON
  key file in any commit, test fixture or log. Testnet keys are generated at runtime
  (`Keypair.random()` plus friendbot) and stored only under `.keys/`, which is git-ignored.
  Public keys (`G...`), contract IDs (`C...`) and transaction hashes are fine.
- **Facts need a source.** Claims about Trustless Work, Circle EURC, Bridge, Privy, Stellar Wallets
  Kit or Stellar itself must come from their code, docs or a recorded testnet run. Anything not
  yet confirmed gets a `TODO(verify)` comment next to it.
- **Style.** English, no em dashes (use commas, colons or parentheses), Apache-2.0 headers are not
  required per file.

## Layout

| Path | Language | Test command |
|---|---|---|
| `contracts/` | Rust, soroban-sdk 26.0.0, Rust 1.93.0 | `./third_party/tw-wasm/fetch.sh && stellar contract build && cargo test` (from `contracts/`) |
| `packages/*` | TypeScript (ESM, NodeNext), vitest | `npm test -w @motored-stellar/<name>` |
| `scripts/` | TypeScript CLIs run with tsx | `npm test -w @motored-stellar/scripts` |
| `examples/order-flow` | TypeScript | `npm test -w @motored-stellar/example-order-flow` |

All TypeScript packages extend `tsconfig.base.json` and pin `@stellar/stellar-sdk` to the same
exact version. If you bump it, bump it everywhere in one change.

## Before you open a pull request

```bash
./scripts/check-secrets.sh          # no seeds, phrases, .env or key files
npm run lint:docs                   # em dashes, secret-shaped strings, banned terms
npm run typecheck
npm test
(cd contracts && cargo test)        # after fetch.sh and stellar contract build
```

- Contract changes: add a test in `contracts/guard/src/test.rs` (it runs against both deployed
  Trustless Work Wasm lineages) or `contracts/claim-registry/src/test.rs`.
- Changes to the claim leaf or Merkle rule: update `packages/claims/test/vectors.json` (generated by
  `npm run vectors -w @motored-stellar/claims`) and make sure the Rust test
  `contracts/guard/src/test_vectors.rs` and `scripts/test/shared-vectors.test.ts` still pass. All
  three implementations must agree byte for byte. See [docs/leaf-format.md](docs/leaf-format.md).
- A new testnet run: append the date, contract IDs and transaction hashes to
  [docs/testnet-proofs.md](docs/testnet-proofs.md).
